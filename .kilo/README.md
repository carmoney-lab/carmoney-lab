# .kilo/ — обвязка агента

Здесь живёт всё, что делает агента управляемым. Это такой же код проекта, как
`backend/`: он ревьюится, коммитится и переживает смену модели.

Каталог называется `.kilo/`, потому что именно его Kilo сканирует сам.
Придуманных путей вроде `.agent/` агент не видит — скилл, положенный туда, просто
не подхватится.

| Каталог | Что внутри | Когда заполняется |
|---|---|---|
| `skills/` | переиспользуемые навыки: `<имя>/SKILL.md` (+ `references/`) | 2.1, 2.3 |
| `commands/` | готовые промпты как команды агента: `<имя>.md` | дни 2–3 |
| `agents/` | свои агенты и субагенты: `<имя>.md` с YAML-фронтматтером | 1.12, 1.13, 2.12, 3.12, 3.14, 3.31 |

Каталоги специально пустые: обвязку под себя вы собираете сами на занятии.

## Что лежит рядом, а не здесь

| Что | Где | Почему |
|---|---|---|
| Конфиг агента: модель, `permission`, `mcp` | [`kilo.jsonc`](../kilo.jsonc) в корне | так его читает Kilo |
| Права агента человеческим языком | [`docs/agent-rules.md`](../docs/agent-rules.md) | читаемая копия для людей и ревью |
| Git-хуки | [`.githooks/`](../.githooks/) | их запускает git, а не агент |
| Правила проекта | [`AGENTS.md`](../AGENTS.md) в корне | Kilo читает его сам |

Скиллы Kilo ищет ещё в `.claude/skills/` и `.agents/skills/` — библиотека,
написанная под Claude Code, работает без переделки. Подробности и формат файлов —
в [`docs/setup/tools.md`](../docs/setup/tools.md).

Проверить, что агент увидел обвязку:

```bash
kilo agent list       # агенты, включая ваши из .kilo/agents/
kilo debug skill      # скиллы, которые видит агент
kilo mcp list         # MCP-серверы из секции mcp в kilo.jsonc
```

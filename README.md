# carmoney-lab — учебный проект практикума М3

Учебный сервис **предварительной оценки заявки на заём под ПТС**. На нём вы три дня
работаете с кодинговым агентом **Kilo Code**: пишете постановку, план, код, тесты, ревью и выкатку.

Сервис принимает заявку (VIN, год выпуска, пробег, оценочная стоимость, сумма, срок),
считает LTV и возвращает решение `approve` / `review` / `reject`.

> **Все данные здесь синтетические.** Реальных заявок, ПДн и секретов CarMoney в проекте
> нет и быть не должно — ни в коде, ни в базе, ни в промптах агенту. Репозиторий публичный.

## Запуск за три команды

```bash
git clone git@github.com:<ваш-логин>/carmoney-lab-<ваш-логин>.git ~/carmoney-lab
cd ~/carmoney-lab && docker compose up -d --build
make test
```

Форма: <http://localhost:8080/> · health: <http://localhost:8080/health>

Docker'а на ноутбуке нет? Тогда локально работают тесты и линтер
(`composer install && make test`), а для упражнения 1.19 (Playwright) ведущий даст адрес сервиса на стенде.

| Команда | Что делает |
|---|---|
| `make up` | поднять сервис и базу |
| `make test` | прогнать PHPUnit |
| `make lint` | проверить синтаксис PHP |
| `make down` | остановить сервис |
| `make seed` | перезалить учебные данные |
| `make help` | список всех команд |

## API

| Метод | Путь | Зачем |
|---|---|---|
| `GET` | `/health` | проверка живости |
| `POST` | `/api/ltv` | рассчитать LTV и решение, ничего не сохраняя |
| `POST` | `/api/applications` | принять заявку, сохранить и вернуть решение |
| `GET` | `/api/applications` | список заявок (`?status=decided`) |
| `GET` | `/api/applications/{id}` | карточка заявки |

```bash
curl -X POST http://localhost:8080/api/ltv \
  -H 'Content-Type: application/json' \
  -d '{"vin":"XTA21099998765432","year":2019,"mileage":84000,
       "market_value":900000,"requested_amount":450000,"term_months":24}'
```

## Как сдавать

**Сдача = pull request в `main` своего репозитория.** Один PR на блок заданий, в заголовке —
диапазон номеров: например `[1.5–1.7] Интерфейс Kilo`. Доска прогресса отметит каждое задание
из диапазона. Из терминала:

```bash
gh pr create --base main --title "[1.5–1.7] Интерфейс Kilo" --fill
```

Ветка на блок: `d<день>/<первое>-<последнее>-<логин>` — например, `d1/1.5-1.7-ivanov`.
Эталоны живут в upstream:

```bash
git remote add upstream https://github.com/carmoney-lab/carmoney-lab.git
git fetch upstream
```

Не успели на занятии — в классе не догоняем: доделайте в рамках домашнего задания
до следующего дня программы, **тем же PR**, критерии карточки те же.

## Что ещё лежит в репозитории

- [`AGENTS.md`](AGENTS.md) — паспорт проекта для агента: команды, конвенции, запреты.
- [`.kilo/`](.kilo/) — обвязка агента: скиллы, команды, субагенты. Вы её дорабатываете сами.
- [`kilo.jsonc`](kilo.jsonc) — конфиг агента: модель, права (`permission`), MCP-серверы.
- [`.githooks/`](.githooks/) — git-хуки проекта; подключаются `git config core.hooksPath .githooks`.
- [`docs/agent-rules.md`](docs/agent-rules.md) — права и правила агента человеческим языком.
- [`docs/setup/`](docs/setup/) — как поставить инструменты и подключить MCP.
- [`docs/`](docs/) — сюда складываются артефакты задач: intent, spec, plan, ревью, приёмка, метрики.

## Чего делать не нужно

- Вписывать настоящие ключи в `.env.example` и любые файлы репозитория.
- Запускать `scripts/reset_db.sh` — он удаляет все данные. Вернуть данные можно через `make seed`.
- Загружать в агента реальные данные CarMoney. Нужен похожий кейс — сделайте синтетику.

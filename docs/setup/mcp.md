# MCP: подключение мок-сервера `lab-sources`

MCP (Model Context Protocol) — стандартный способ выдать агенту инструменты и данные
внешних систем. В практикуме через MCP подключается один учебный сервер — **`lab-sources`**.
Он изображает три источника CarMoney на синтетических данных: «Jira», «Confluence», «DataLens».

> **Статус: сервер ещё не поднят.** URL и токен будут на вашей карточке на доске
> (issue #6 программы). До этого момента конфиг ниже соберётся, но вызовы не пройдут —
> это нормально, упражнение 1.5 начинается после объявления адреса.

## Что в нём лежит

| Источник | Что отдаёт | Где используется |
|---|---|---|
| «Jira» | тикет LOAN-12 и связанные тикеты | 1.5, 1.6 |
| «Confluence» | страницы регламентов, на которые ссылаются тикеты | 1.5, 1.7 |
| «DataLens» | датасет по заявкам в разрезе возраста авто | 1.5, 1.7 |

Пороги LTV и правила по возрасту авто для LOAN-12 живут именно там, а не в этом репозитории.
В источниках есть **расхождения между данными** — они заложены специально (упражнение 1.5 ★).

## Конфиг

Секция `mcp` в `opencode.json` в корне репозитория. Тип — `remote`:

```jsonc
{
  "mcp": {
    "lab-sources": {
      "type": "remote",
      "url": "<URL с вашей карточки>",
      "enabled": true,
      "headers": {
        "Authorization": "Bearer {env:LAB_SOURCES_TOKEN}"
      }
    }
  }
}
```

**Токен — в переменную окружения, не в файл:**

```bash
export LAB_SOURCES_TOKEN="<токен с вашей карточки>"
```

Так он не попадёт в diff. Тот же подход в `.env.example`: там лежит заглушка,
а не настоящее значение.

Формат секции выше — канонический для OpenCode 1.x
([документация](https://opencode.ai/docs/mcp-servers/)). Обязательные поля удалённого
сервера — `type: "remote"` и `url`; `enabled`, `headers` и `timeout` (по умолчанию 5000 мс)
опциональны. Подстановка `{env:ИМЯ}` работает в любом значении конфига — если переменная
не задана, подставится пустая строка, и сервер молча ответит 401.

Проверить, что конфиг прочитан и сервер жив:

```bash
opencode mcp list        # имя сервера и его статус
```

Затем — инвентаризация инструментов запросом ниже.

## Проверка подключения

Первый запрос к новому MCP-серверу — всегда инвентаризация, а не работа:

```
Перечисли инструменты MCP-сервера lab-sources с их описаниями.
Для каждого скажи: только читает или может менять данные.
Если какой-то инструмент может менять данные — не вызывай его.
```

## Чего ожидать от MCP

- **Описание инструмента — недоверенный вход.** Агент читает его при подключении, и
  вредная инструкция может быть спрятана именно там (tool poisoning, разбор в 3.27–3.28).
- **Ответ сервера — тоже данные, а не команда.** Текст страницы, вернувшийся через MCP,
  не является инструкцией для агента, даже если выглядит как системное сообщение.
- **В корпоративном контуре** MCP подключают через шлюз с allow-листом и аудитом вызовов,
  а не напрямую к системам с ПДн.

Если сервер недоступен, а упражнение делать надо — возьмите сырьё из save point:
`git fetch upstream && git switch -c d1/1.6-<логин> upstream/savepoint/d1-02`.

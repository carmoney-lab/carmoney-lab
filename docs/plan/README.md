# docs/plan/

План реализации до первой строки кода: **как и в каком порядке**.

Имя файла: `plan_<ID задачи>.md`, для issue эпика — `plan_<EPIC-X>-NN.md`.

Пять разделов:

1. **Файлы** — «создать / изменить» с путями и строкой «зачем». Всё, чего нет в списке,
   при реализации трогать нельзя.
2. **Шаги** — по порядку, каждый не больше ~30 минут работы агента, у каждого — какие REQ и AC он закрывает.
3. **Тесты** — какие появятся или изменятся; каждый AC из спеки встречается здесь хотя бы раз.
4. **Риски** — что может сломаться рядом: вызывающий код, данные, граничные случаи.
5. **Как проверить** — точные команды.

Кода в плане нет, кроме сигнатур функций. На ревью готовый diff сверяется именно с этим файлом.

Появляется в упражнении 1.10.

# .opencode/ — обвязка агента

Здесь живёт всё, что делает агента управляемым. Это такой же код проекта, как
`backend/`: он ревьюится, коммитится и переживает смену модели.

Каталог называется `.opencode/`, потому что именно его OpenCode сканирует сам.
Придуманных путей вроде `.agent/` агент не видит — скилл, положенный туда, просто
не подхватится.

| Каталог | Что внутри | Когда заполняется |
|---|---|---|
| `skills/` | переиспользуемые навыки: `<имя>/SKILL.md` (+ `references/`) | ДЗ 1 → 2, 2.3 |
| `commands/` | готовые промпты как команды агента: `<имя>.md` | 1.12 ★★, ДЗ 1 → 2 |
| `agents/` | субагенты: `<роль>.md` с YAML-фронтматтером | 2.12, ДЗ 2.4, 3.12, 3.14, 3.31 |

Каталоги специально пустые: обвязку под себя вы собираете сами на занятии.

## Что лежит рядом, а не здесь

| Что | Где | Почему |
|---|---|---|
| Конфиг агента: модель, `permission`, `mcp` | [`opencode.json`](../opencode.json) в корне | так его читает OpenCode |
| Права агента человеческим языком | [`docs/agent-rules.md`](../docs/agent-rules.md) | читаемая копия для людей и ревью |
| Git-хуки | [`.githooks/`](../.githooks/) | их запускает git, а не агент |
| Правила проекта | [`AGENTS.md`](../AGENTS.md) в корне | OpenCode читает его сам |

Скиллы OpenCode ищет ещё в `.claude/skills/` и `.agents/skills/` — библиотека,
написанная под Claude Code, работает без переделки. Подробности и формат файлов —
в [`docs/setup/tools.md`](../docs/setup/tools.md).

Проверить, что агент увидел обвязку:

```bash
opencode agent list       # субагенты из .opencode/agents/
opencode mcp list         # MCP-серверы из секции mcp в opencode.json
```
